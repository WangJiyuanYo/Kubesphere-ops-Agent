# PIT-baeeceee19e9: 部署生命周期身份不能作为应用健康版本

| 字段 | 值 |
| --- | --- |
| ID | `PIT-baeeceee19e9` |
| 日期 | `2026-11-13` |
| 领域 | `api` |
| 标签 | 恢复验收, 版本契约, 跨系统 |
| 来源 | 部署运维 Agent 2026-11-13 业务闭环复审与修复 |

## 需求

平台发布、恢复预算与应用版本验收使用各自正确且冻结的身份。

## 现象

平台任务版本与应用真实版本不相同，健康应用一直验收失败，页面从 CR 预填的版本也被平台拒绝。

## 错误做法

```text
健康响应 version 与 run.deploymentVersion 比较，转交页面直接采用 CR releaseVersion。
```

## 根因

把跨系统同名版本字段视为同一业务语义，生产者与消费者分别使用理想夹具掩盖差异。

## 修复方案

```text
平台绑定 applicationVersion，Agent 独立冻结并校验；生命周期版本由受权平台读取，继续用于原任务与预算。
```

## 预防规则

跨系统标识先定义生命周期语义与真实来源；用两个不同的版本值做生产者和消费者契约回归，禁止复用同一夹具值掩盖差异。

## 验证

最终 Agent verify 230 项全通过，平台专项 85 项全通过；包含生命周期与应用不同版本、版本漂移拒绝及双库完整流程。
