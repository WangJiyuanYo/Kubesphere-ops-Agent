# PIT-ce14e1ebc32e: 完成的 Job Pod 被当作异常占满采证名额导致遗漏真正失败组件

| 字段 | 值 |
| --- | --- |
| ID | `PIT-ce14e1ebc32e` |
| 日期 | `2026-11-13` |
| 领域 | `workflow` |
| 标签 | job, 有界采证, 证据缺口, 采样排序 |
| 来源 | 独立 Agent 真实只读排查与有界采证回归 |

## 需求

在固定归属和采样预算内，优先采集真正失败组件，避免将采样结果当作完整清单。

## 现象

CR 报告消息队列安装失败，但采证只列出其他已完成的安装 Pod，模型无法定位失败容器。

## 错误做法

```text
按 Ready 条件将 ready=false 的 Pod 放前面，再按名称排序取前四条；关联工作负载仅用于归属展开而不保留状态。
```

## 根因

已成功完成的 Job Pod 通常 Ready=false。仅按 Ready 二分会把 Succeeded 和 Failed 混在一起，按名称截断遗漏靠后的失败 Pod。

## 修复方案

```text
保留最多八个已证明归属的工作负载状态；优先失败或 CR 引用的归属工作负载及其 Pod，再按容器失败、未就绪、健康、成功完成排序；超出采样上限明确记录缺口。
```

## 预防规则

覆盖大量成功 Job 与靠后失败 Job 混合场景；名称提示只能在已证明归属范围内影响排序，不能成为授权；保持请求、对象、日志和时间预算。

## 验证

ReadOnlyEvidenceCollectorTest 四项通过，含五个完成 Pod 与靠后失败 Pod 场景。完整 Maven verify 240项通过。真实只读复验已优先捕获失败 Job 的 BackoffLimitExceeded 和对应容器 exitCode=1，并明确 POD_SAMPLE_LIMIT 及日志事件 HTTP_403，不把缺口当成功。
