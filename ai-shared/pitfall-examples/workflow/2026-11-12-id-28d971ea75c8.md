## 需求

修复会话目标漂移、不同任务环境的证据混用及模拟记忆进入真实调查。

## 现象

修改同一连接的命名空间后旧会话读取新环境；模拟 Run 与另一目标的 Pod 同时进入上下文。

## 错误做法

```text
createSession 只检查 connectionId/runId 分别存在；Session 仅保存 connectionId；每轮用最新配置采证。
```

## 根因

持久化对象引用是可变配置的定位方式，不是授权目标或证据来源的不可变身份；进程模式也不代表一次只读调查的实际环境。

## 修复方案

```text
会话事务内冻结 API 与命名空间摘要，每轮采证前校验；恢复任务冻结环境和执行集群并在状态机前核对；跨来源关联需证明任务与连接一致；自动召回按实际来源范围过滤。
```

## 预防规则

对话、调查、任务、命令和记忆均须携带显式来源身份。编辑目标不能让历史上下文迁移；相同目标的凭据轮换可以继续。无法证明来源时禁止真实执行及自动经验召回。

## 验证

全新 SQLite 与独立 PostgreSQL 测试库的 DiscoveryContract 回归覆盖目标修改、凭据轮换、模拟/真实拒绝、执行模式变化及 FTS5 来源隔离；DeploymentIdentityTest 核验匹配与规范化。完整 Maven verify 共 184 项，0 失败、0 错误、0 跳过。日志 tmp/goal-foundation-verify.log。
