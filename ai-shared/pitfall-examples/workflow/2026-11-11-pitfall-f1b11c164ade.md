# PIT-f1b11c164ade: 等待批准状态也必须进入到期回收队列

| 字段 | 值 |
| --- | --- |
| ID | `PIT-f1b11c164ade` |
| 日期 | `2026-11-11` |
| 领域 | `workflow` |
| 标签 | approval, deadline, state-machine |
| 来源 | src/main/java/com/lanhao/ops/persistence/JdbcRunStore.java 与 RunEngine.java |

## 需求

部署监控有总时限，等待批准不能永久占用同一部署任务的活动监控名额；过期方案不得执行。

## 现象

活动任务唯一约束包含 WAITING_APPROVAL，但调度查询排除了该状态，批准入口也不检查截止时间；批准任务可无限停留并阻止重新注册。

## 错误做法

```text
claim 查询只包含 MONITORING、DIAGNOSING、RETRY_WAIT、EXECUTING、VERIFYING；approve 只检查 state 和 planId。
```

## 根因

状态机总时限只在执行 step 时检查，状态不入队就无法到达该检查；授权入口也缺少独立时间前提校验。

## 修复方案

```text
将 WAITING_APPROVAL 纳入认领 SQL 和到期索引，等待时把 due_at 设为绝对截止时间；过期转 MANUAL_REQUIRED。approve 同时校验时限，先提交过期终态再返回冲突，释放活动任务约束。
```

## 预防规则

所有具有生命周期上限的等待状态都必须有持久化唤醒或到期回收路径；批准、恢复等入口需独立复核时间前提；错误返回不得回滚必须提交的失效状态。

## 验证

修复前 JdbcRunStoreTest 的 waitingApprovalsRemainEligibleForDeadlineChecks 和 expiredApprovalIsRejectedAndReleasedForNewMonitoring 稳定失败，修复后连同完整 43 项 Maven 测试通过，使用真实 PostgreSQL 验证约束释放。
