## 需求

部署诊断图需要在多个节点传递命令计划、资源范围和记忆引用，且并发诊断不能混用任务范围。

## 现象

新增命令节点后，嵌套记录中的目标列表经 Graph 状态复制后出现 Map 与记录类型混用，导致 JsonMappingException；在同一图先执行有任务范围的诊断，再只传证据时，遗漏 scope 输入会沿用上一次范围，触发错误任务租约校验并丢失诊断引用。单测单独运行可通过，组合执行失败。

## 错误做法

```text
state.put("commands", work); if (scope != null) input.put("scope", scope);
```

## 根因

当前 Graph 库的复杂状态复制不能可靠保留嵌套泛型记录类型；复用编译图时，未覆盖的输入键可能保留旧值。命令执行范围属于授权上下文，不能依赖泛型推断或省略字段来清空。

## 修复方案

```text
跨节点复杂数据均写入 JSON 字符串，在节点中用明确 DTO 类型读取；每次调用都执行 input.put("scope", json.writeValueAsString(scope))，无范围也写 JSON null；使用可中断互斥保护复用图的调用，执行器独立校验数据库租约与资源目录。
```

## 预防规则

Graph 中的任务、资源和授权上下文须每次显式覆盖；复杂数据使用可验证的序列化契约；同一编译图的调用必须隔离，并用连续调用与并发测试验证不会继承其他任务身份。
