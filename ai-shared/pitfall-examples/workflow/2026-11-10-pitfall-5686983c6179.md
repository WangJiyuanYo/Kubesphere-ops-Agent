# PIT-5686983c6179: 恢复响应丢失后须先找回动作身份再核验资源代次

| 字段 | 值 |
| --- | --- |
| ID | `PIT-5686983c6179` |
| 日期 | `2026-11-10` |
| 领域 | `workflow` |
| 标签 | generation, idempotency, recovery |
| 来源 | src/main/java/com/lanhao/ops/workflow/RunEngine.java 与对应回归测试 |

## 需求

Agent 崩溃或恢复接口响应丢失后，应沿用已持久化动作键接管本次恢复，并识别自身恢复引起的发布代次变化。

## 现象

恢复已经受理并递增 retrySequence 时，本地仍为 EXECUTING 且尚无 recovery 身份；如果先按原 generation 采证，会把自身恢复当成并发发布并错误停止。

## 错误做法

```text
case EXECUTING -> { Evidence fresh = deployment.observe(run); run.recovery = deployment.retry(run); }
```

## 根因

外部副作用和本地快照不能原子提交；响应丢失时，资源已改变而本地身份尚未确认。单纯在执行前检查旧代次，无法区分新发布与本动作的效果。

## 修复方案

```text
先通过固定 actionKey 查询平台现有 recovery；匹配时保存该身份并进入 VERIFYING。随后仅允许同一恢复身份下其他配置摘要不变的一次 retrySequence 和 generation 递增。未查到动作时才重新采证和幂等下发。
```

## 预防规则

所有可重放外部动作须先落盘意图与幂等键；接管时先对账动作身份，再解释目标状态变化，不通过生成新键掩盖不确定结果。

## 验证

RunEngineTest.findsAcceptedActionBeforeObservingItsOwnGenerationChange 验证先找回身份且不再下发；KubernetesDeploymentPortTest.findsLostResponseByPersistedRequestKey 验证平台查询匹配；onlyOwnRecoverySequenceMayAdvanceGeneration 验证限定代次变化。
