## 产品目标与范围

使 Agent 对话能够实际读取故障证据，并让操作员核对执行记录。原先普通对话仅提供少量 Pod 名称、phase、Ready 摘要，模型无法据此判断容器退出原因；现在勾选「自动只读排查」后执行有审计的采证，再向模型提供实际结果。

采证直接调用所选 KubeSphere 连接的 Kubernetes API，支持 Pod 状态、按 UID 过滤的事件、明确容器的当前及上次退出日志，相当于对应 `kubectl get / logs` 的只读 API 操作。不依赖本机 kubectl，也不启动 Shell。恢复流程中可选的 CLI 命令链继续使用独立执行身份，不与此功能混用。

## 角色、前提与流程

沿用 OPERATOR 认证和共享工作空间。操作员在对话上下文选择连接，新会话冻结 API 与命名空间；选择后默认开启只读排查，发送前可关闭。未关联或关闭时不会因问题文字、模型建议、历史消息或记忆自动连接其他环境。

本轮流程为 `generateCommands → assessCommands → executeCommands → analyzeResults`，然后使用已采集证据、实际来源范围的记忆及历史消息生成回答。各节点独立，跨节点数据明确 JSON 编解码，每次调用单独创建 Graph 和审计上下文，不继承上次目标。

1. 生成计划：Java 根据冻结目标生成固定只读操作，不使用模型拼 URL、Shell 或自由参数。这样只需要一次模型分析调用，模型服务故障不会阻止已经完成的采证记录落库。
2. 安全校验：核对会话身份、连接版本、当前轮次租约；实际请求仍逐条检查命名空间、资源与参数白名单。拒绝 Secret、exec、写资源、任意地址、跨集群、watch、额外参数及超限输出。
3. 执行采证：先持久化计划及每个请求的执行意图，再执行 GET。使用所选连接保存的 Token / CA，保持 TLS 主机名校验且不跟随重定向，不把页面凭据写入命令行。
4. 分析结果：保留真实请求、HTTP 结果、采证时间和脱敏证据，标记缺口后再交给模型；HTTP 成功不代表内容一定完整，也不构成恢复授权。

## 采证范围与预算

普通连接会话在冻结命名空间内分页读取 Pod，最多 500 个对象，优先用户问题中匹配的完整 Pod 名称，否则优先失败、等待、未就绪的 Pod。每轮详细检查最多 2 个 Pod、每个最多 2 个异常优先的普通或初始化容器；未覆盖的对象明确标记采样缺口，可指定 Pod 名称新问一轮。

记录 phase、Ready、条件、容器状态、重启次数、退出码和上次退出状态。事件按 Pod UID 过滤，每个 Pod 最多 4 条；日志固定每次末尾 60 行、最多 4096 字节，持久化摘要最多保留 1200 字符。发生过重启且有上次退出状态时同时尝试 previous 日志。状态来自本轮采样，不等于持续监控结果。

关联部署发现的会话保持 CR 身份 / generation 与 ownerReference 归属校验，沿既有目标采证范围执行，不扩大到整个命名空间。容器日志读取前后均复核 Pod UID；同名 Pod 被替换时丢弃日志，不用作当前目标的原因证据。

采证执行预算为 8 秒，在请求边界检查；HTTP 单次连接及读取超时为 2 秒，最多 24 个请求，列表响应最多 1 MiB / 500 对象。预算不足或分页异常保留已确认事实并标记缺口，不无限重试。目标 CR 的前后身份读取另有每次 2 秒的预算。模型继续遵循原有单次读取预算，失败不自动重发。

`BUSINESS_DICTIONARY_OR_CONFIG`：只读操作、请求白名单和采证上限属于安全策略代码常量，不作为运营字典，也不由用户或模型调整。连接地址、命名空间和凭据仍为操作员维护的运行配置。

## 审计、状态与异常

PostgreSQL V14 / SQLite V9 建立轮次采证记录，随主存储持久化；包含冻结目标、阶段、逐条真实 API 路径、时间、结果及脱敏证据，无 Token、CA 或未筛选的资源 spec。记录与对话轮次关联，未提供自动清理入口。

阶段为 APPROVED、RUNNING、COMPLETED、PARTIAL、FAILED；请求为 RUNNING、SUCCEEDED、FAILED。中断、租约失效且未确认完成的执行在查询时显示 UNKNOWN，不将意图当成成功。请求重放直接返回原轮次，不重跑 Graph、集群读取或模型；用户重新发送才创建新轮次。

连接变化、原身份失效或租约过期停止后续读取，旧执行者不能保存成功结果或自动复盘。原始日志和事件是数据，不授予权限，不接受内嵌执行指令。模型报错时已落库采证仍可单独查看。

401 明确 Token 无效或过期。403 明确资源和动作，例如 `events list` 或 `pods/log get`；不回显上游错误正文，不把权限问题当作资源不存在、空集群、网络正常或已确认根因，也不自动修改 RBAC。

## 页面与接口

成功、失败的已结束轮次，只要请求过集群采证，均可展开「本轮集群采证记录」，查看实际 API 请求、状态、权限提示和证据摘要，并显式刷新。历史无审计的轮次显示未保存，不补执行。证据始终按纯文本展示；助手的成功回答独立支持安全 Markdown。

`GET /api/console/sessions/{sessionId}/turns/{turnId}/inspection` 需要 OPERATOR，返回 JSON `{available, report}`。校验消息确实属于当前会话；无审计返回 available=false，错误会话返回 404。该查询不调用模型或集群。

## 验收标准

1. 普通连接对话实际执行 HTTP 读取，模型获得容器退出状态、事件、当前与 previous 日志；不是仅修改提示词。
2. 每个 GET 到达契约服务前，数据库已存在该路径的 RUNNING 审计；完成结果在两种真实主库可恢复。
3. 关闭采证或无连接不产生集群请求；重复同一消息不重复执行；失败模型的采证仍可查看。
4. 403 显示具体资源权限，保留已取得的状态，原始错误正文及凭据不泄漏。
5. Pod UID 替换不采纳旧日志；连接换址、租约失效停止后续请求，未完成请求显示 UNKNOWN。
6. 并发不同连接的请求和审计互相隔离，未调用部署恢复或既有 CLI 命令执行表。
7. 注入路径、跨命名空间、Secret、exec、危险参数、非固定日志上限均被拒绝。
8. 页面显示实际请求与独立证据，窄屏不整体溢出；历史无记录不伪造补采结果。

## 真实环境权限边界

真实上海环境之前已观测到事件和日志 403。本功能能够定位和展示权限缺口，不能凭代码修改获取集群未授予的权限。管理员应核对该连接实际身份在目标命名空间的 pods get/list、events list、pods/log get，以及部署发现相关工作负载 / CR 的 get/list；不需要授予 cluster-admin。权限调整由原环境正常授权流程完成，Agent 不自动绑定角色。

本机 HTTP 替身、双库测试、UI 验收和真实集群验收分别记录；不能把合成日志当作上海站点已取得的真实根因。旧运行实例需切换到本次构建包才具有新链路。

本机更新入口：`scripts/update-local-readonly-agent.cmd -Restart`。该脚本核对已验证构建哈希、8100进程与SQLite路径，拒绝活动恢复 / 对话 / 调查，在线备份数据库和主密钥后更新。仅用于当前本机 SQLite / DEMO / 平台目录关闭实例；不读取平台 DPAPI 凭据。脚本5.1/7语法通过，但实际服务切换被自动审批拒绝，需操作员本机执行。
