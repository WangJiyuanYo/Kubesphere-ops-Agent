## 产品目标与范围

为运维人员提供部署监控、故障采证、中文排障方案、受控重试和恢复验收。项目独立部署，集成现有 webapp-operator 的四类交付 CR 与平台恢复 API。

支持模拟演示和 Kubernetes 适配。手工注册同一平台任务、同一集群内 1–10 个已存在资源；平台可推送部署事件，Agent 先持久化事件，再从受权发布快照发现并绑定尚未创建的资源。可显式启用受权平台分页目录以观察站点及 CR 创建前阶段；目录不自动注册恢复任务，用户确认后再转交。当前不自动改代码、修改配置、恢复数据或回滚发布。

新增可选[站点阶段与自动托管](站点开通与自动托管_PRD.md)：按策略自动调查并经原严格转交服务关联唯一 Run。APPROVAL 不受全局 autoRetry 自动放行；AUTO_LOW_RISK 还须独立开关与验收记录引用。策略停用阻止新动作，已受理动作按原键只读对账。Run 同时冻结平台 API；原真实账本缺少平台身份或平台换址时停止接管。模型调用先保存意图，同证据未知结果不自动重放。未增加新的恢复类型，现场恢复仍须单独验收。

## 用户角色与场景

调用方为持有独立 API 凭据的运维人员或部署平台，API 账号管理的所有任务属于同一信任域。项目不提供多租户用户登录与租户间的数据隔离服务。平台 Token 的数据权限由现有平台授权体系控制，Kubernetes 可读范围由命名空间 Role 控制。

## 当前功能规则

1. 使用请求幂等键、平台任务字符串 ID、资源类型、命名空间、名称、UID、generation 创建监控。严格模式另需发布版本和服务端验收目录，注册时验证平台归属。重复请求返回原任务；同键不同目标、版本或目录拒绝。已有请求的幂等查询不因后续资源变化而失效。
2. 同一平台任务只允许一个活动监控。固定允许命名空间，拒绝未授权目标；不从客户端接收平台地址、验收地址或执行命令。
   新建任务冻结运行环境与执行集群 API；每步推进前核对当前执行身份。更换进程模式或集群后旧任务停止，缺少来源的旧账本不得取得真实集群执行权限。
3. 明确失败或阶段连续 10 分钟无进展时生成中文方案：根因假设、检查步骤、修复步骤、验证方式和方案来源。采证保存资源身份、代次、时间、来源和采集缺口。AI 不可用时回退规则手册。
4. 仅当前代次 CR 的明确暂时性故障可授予重试，当前容器认证、配置、OOM、容量、存储和数据错误优先否决。原始日志、历史事件或普通数字 503 不能单独授予执行权限；可选采证失败保留已收集证据，并禁止本次自动动作。DEMO 默认自动模式；Kubernetes 示例等待批准，严格平台契约就绪后才可启用自动恢复。
5. 每个任务默认最多 2 次恢复意图，可配置 1–3 次。恢复请求使用固定动作身份；响应丢失不得续发新键。每次执行前重新验证目标和当前故障类型。
6. 禁止由模型修改策略、扩大权限或直接执行操作。高风险或证据不足时转人工，并保留方案和事件。
7. 未启用自动模式时，批准操作必须对应当前 planId；旧方案、非低风险方案、错误状态均拒绝。
8. 成功须当前代次 CR 全部 Ready、平台任务和本次恢复身份成功、任务目录指向的应用健康为 UP 且 version 等于绑定发布版本，连续通过 3 次。Pod Ready 或恢复请求受理单独均不代表成功。兼容模式只支持固定地址的健康检查。
9. 部署事件按平台任务和不可复用发布版本去重，同一发布共享唯一任务和恢复预算。不同事件号不能重开终态任务；同版本直接注册同样不能重置预算。旧任务仍活动时，新发布事件持久化等待。
10. 严格恢复请求携带冻结版本、snapshotToken、目标代次、配置摘要、重试序号和手册版本。平台须原子核验并幂等受理；HTTP 409 / 412 停止旧任务，不降级到旧接口。兼容旧接口必须显式关闭严格模式及自动恢复，仅供人工批准试点。
11. 可执行手册目录当前提供 platform-transient-retry v1，具有前置条件、执行器、验证和补偿说明。方案中的手册必须属于该目录；模型不能创建新执行类型。
12. 等待批准和终态时在同一事务写入通知。通知默认关闭投递，但事件持久化；开启后按固定事件身份签名发送，失败退避，默认最多 8 次，耗尽进入 DEAD。仅运维显式重投可重置投递预算。接收方须核验签名、时间窗口并去重。

## 业务流程与状态

任务经监控、诊断、等待重试或批准、执行、验证，最终为成功、失败、人工处理或取消。验证默认最多等待 5 分钟，超时后在预算内重新诊断，预算耗尽转人工。验证前和响应后均核验时限，已超时的健康结果不得计入成功。任务执行总时限默认 60 分钟；等待批准时在总截止时间检查，过期自动转人工并释放活动任务约束，批准入口同时拒绝过期方案。

验证阶段刷新并保存平台本次恢复状态。恢复明确失败后立即按剩余预算重新诊断；恢复身份被替换、消失或被平台标记为 SUPERSEDED 时停止旧任务，不继续执行旧方案。

原目标 UID 被替换、删除、generation 或其他配置发生非恢复变化时停止旧任务。每次恢复意图冻结本次动作的资源代次和发布重试序号；自身平台恢复仅允许其他配置摘要不变、在该冻结基线上的一次递增，不得重复使用同一恢复身份接受第二次递增。旧任务缺少动作基线时按最初绑定代次保守核验。更换版本后须创建新监控。

取消只适用于尚未下发外部动作的任务；执行与验证阶段不能通过取消接口回撤外部操作。终态可以继续查询。

事件任务从 DISCOVERING 开始；受权快照暂无目标或 targetsComplete=false 时继续等待，完整目标集合就绪后一次绑定并进入 MONITORING。资源发现默认最多等待 10 分钟；前置阶段明确失败则停止并保留失败原因。事件与既有版本的验收目录冲突时将事件隔离为 VERIFICATION_PROFILE_CONFLICT，不阻塞其他事件。

## 数据与接口语义

任务快照、诊断、动作身份和最近最多 100 条正常状态事件保存在独立主库中，默认 PostgreSQL，可选完整 SQLite 单机模式。状态事件另写追加式审计表，不随快照裁剪删除。采证 / 接口异常事件每次追加，达到三次即终止自动流程。平台 64 位 ID 通过字符串传输。两种数据库均用唯一约束保护请求幂等、活动任务唯一性和发布周期预算，租约保证过期执行者不能回写新状态。SQLite 依赖 IMMEDIATE 写事务，按本地持久盘单实例部署，不承诺 PostgreSQL 的多实例容量。

诊断 Graph 依次完成脱敏、规则分类、已验证记忆召回、结构化命令生成、安全分析、受控执行、结果分析和最终诊断。命令默认关闭；启用后最多执行 3 条任务范围内的只读 kubectl 采证，意图先持久化，安全拒绝或失败否决自动恢复，不能扩大原授权。完整规则见 [kubectl受控排查_PRD.md](kubectl受控排查_PRD.md)。自动召回最多 3 条当前环境的已验证记忆，保存真实引用；历史建议不能改变分类、权限、恢复预算与当前验收标准。经过恢复并最终成功的任务与记忆出队记录同事务提交，异步幂等归档；归档失败不回退任务终态。记忆完整规则见 [SQLite与排障记忆_PRD.md](SQLite与排障记忆_PRD.md)。

提供任务创建、列表、详情、按方案批准、取消、事件接入与查询、手册目录、审计、通知状态和 DEAD 重投接口。所有业务接口及指标均要求认证，公开简略健康端点及控制台静态登录壳。控制台提供任务查看、模型配置、KubeSphere 只读连接与 Agent 对话，详见 [Agent管理控制台_PRD.md](Agent管理控制台_PRD.md)。严格契约的原子保证依赖平台在发布锁或事务内实现前提核验；本项目只交付 Agent 侧，不宣称现有平台已具备该保证。

## 异常与恢复

模型不可用回退手册；API 访问或采证连续三次失败转人工，保留原动作身份。进程重启后接管到期租约，重用已持久化动作键。权限拒绝、资源容量不足、认证失败、存储和数据问题不自动重启或删除资源，交由运维按方案修复并正常发布。

真实模式在配置绑定阶段完成凭据、HTTPS 地址、命名空间与时限校验，配置无效时不得启动任务调度。时限必须为正数，租约至少为 120 秒；地址不接受内嵌用户信息、查询串或片段。

调度默认每实例 4 个工作槽位，先预留槽位再认领任务；不预取排队任务。租约定期续期，续期失败停止后续外部动作。单步默认 75 秒，采证默认 45 秒，独立定时器中断超时任务；不响应中断的线程继续占用槽位，不通过新建无限线程绕过上限。采证预算在请求边界检查，正在进行的请求仍受其连接和读取时限限制。

## 配置选型

`BUSINESS_DICTIONARY_OR_CONFIG`：重试上限、等待时限、并发槽位、自动执行开关、部署命名空间、验收目录、严格契约开关及通知策略属于有类型的服务端配置；状态、动作类型、CR 类型和手册执行器属于代码枚举及版本化目录。安全拒绝规则是版本化代码策略，模型无权变更。控制台仅提供模型和对话只读连接的在线配置入口，不修改恢复策略或工作流集群身份。

诊断优先使用已保存的控制台模型配置；明确关闭时使用规则手册，没有保存过配置时兼容启动环境的模型设置。模型不可用回退手册，原 Graph 的脱敏、分类和策略门禁继续生效。聊天模型只提供分析，无恢复执行工具。

## 验收标准

- 模拟部署失败后生成方案、自动恢复一次并连续验证成功，事件可查询。
- 同一请求重复创建返回同一任务，同键不同目标返回冲突；超出安全整数的任务 ID 原样保存。
- 同一任务不得被两个执行者同时认领；过期 owner 不可保存结果。
- 恢复响应丢失后沿用同一个动作键和同一次预算。
- 当前计划批准后若证据变为认证错误，不执行原动作。
- CR 旧 observedGeneration、应用 DOWN、错误恢复身份均不能通过验收。
- 无模型密钥的演示服务可启动；匿名业务请求拒绝，合法凭据可以创建并查询任务。
- 配置变化、资源替换和预算耗尽均停止自动动作，保留排障信息。
- 过期批准任务可以被调度回收，批准请求返回冲突且过期状态提交落盘，释放活动任务约束；严格模式下一发布使用新版本注册，不能重置旧版本预算。
- 任务详情中的恢复状态随平台变化同步；恢复失败、被替代和超时不得继续累计成功次数。
- 同一恢复请求引起第一次代次变化后，再次递增必须被拒绝。
- 非法真实环境配置、零时限或过短租约在绑定阶段失败。
- 重复部署事件、终态后的同版本事件和不同请求键不能续发预算；旧发布活动时新事件不丢失。
- 当前 CR 故障证据在可选日志采集失败时保留；采证缺口、容器 OOM 或历史日志均不能授予自动恢复。
- 严格请求带冻结前提，错误发布版本、资源归属或 HTTP 409 / 412 停止执行；未知手册不可执行。
- 应用 UP 但版本不符或探测到其他服务不能通过；健康请求不泄漏平台 Token。
- 无工作槽位不认领新任务，超时但未退出的线程仍占槽；续租失败阻止后续动作。
- 通知与任务终态共同提交；相同通知重复保存不重复建单；失败重投保持事件身份，耗尽进入 DEAD。

## 依赖与现场边界

真实模式依赖平台服务账号、HTTPS 平台快照和原子恢复契约、服务端应用验收目录、只读 Kubernetes RBAC 及持久化主库（PostgreSQL 或 SQLite）。记忆需要持久化 SQLite 文件；PostgreSQL 模式下也须挂载记忆数据卷。平台需接入事件发送并实现新契约；现场仍需验收平台幂等记录、Operator 消费确认、发布互斥、完整所有权链、模型可用性和日志脱敏范围。Helm 内部无 CR 所有权链的 Pod 日志与中间件协议验收不在当前自动采集范围。自动配置修复、扩容和回滚需要另行定义平台执行与补偿契约。

审计、报告及发布去重账本当前不自动删除；保留策略须避免清理后历史事件重开恢复预算。外部通知为至少一次，接收方必须幂等；本次未向真实外部通知系统发送消息。

## 严格来源与验收版本

平台快照必须提供规范化集群 API，与独立执行身份一致；缺失或更换时停止。部署生命周期 version 用于原任务与恢复预算，applicationVersion 用于应用健康验收，两者分别绑定并冻结，不能用平台任务身份冒充应用发布版本。平台令牌纳入集群身份及发布前提；目录或只读连接不授予恢复权限。

普通任务和发现案例均可批准当前 planId 或停止尚未下发的恢复。只有可信动作凭据与连续稳定验收均满足才能自动归档有效恢复经验；自然收敛只保存待确认复盘。
