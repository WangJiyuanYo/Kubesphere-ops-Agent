## 1. 目标与范围

Agent 从已经发生的调查、回复和恢复轨迹中形成可追溯复盘，让运维修订、验证后用于下一次同来源问题排查。学习采用“总结落库—核验—检索召回”，不训练模型权重，不允许经验修改动作权限或恢复预算。

本轮新增无 CR 平台前置失败的规则调查 DRAFT，以及与 Run 终态同事务的恢复效果账本，区分受控恢复验收成功、自然收敛、恢复未验收成功、转人工 / 失败与取消；控制台展示样本数量、手册 / 策略版本和记忆引用。该统计只覆盖升级后写入的终态，不回填旧任务，不意味着已经实现候选知识评测 / 灰度发布，不改变下述 VERIFIED 门禁。详情见[站点开通与自动托管 PRD](站点开通与自动托管_PRD.md)。

## 2. 用户角色与场景

沿用共享工作空间的 OPERATOR。运维从成功回复下查看自动复盘，或在调查案例中打开方案、对话及关联恢复形成的总结；填写实际验证依据并确认后，下次相似故障可召回该经验。未验证假设可保留、编辑或归档。

## 3. 当前规则

- 关联来源的成功对话：保存问题和建议，明确“未执行、未验收”；模型失败、失败轮次重放和未绑定会话不自动总结。
- 完成的发现调查：保存现场摘要、根因假设、检查计划、修复建议、建议验证和采证缺口，明确未执行恢复。
- 失败、转人工、取消、未经实际恢复的成功终态：保存实际状态轨迹、尝试次数、动作身份和未取得验收的事实，不把结束当成功。
- 以上均由固定模板生成 REFLECTION / DRAFT，不额外调用模型；自动工作器拒绝自授 VERIFIED。正文脱敏并按记忆容量截断。
- 只有固定动作键、可信成功受理凭据、实际尝试、稳定验收与方案均齐备的任务，才按 RUN 规则自动成为已验证经验。自然收敛、仅扣意图预算或无法证明受理时生成 DRAFT，不能把建议写成已执行。归档保留原诊断证据，根因标记为假设。
- 来源结果和出队快照在主库同事务提交；后台每 5 秒最多处理 10 条，30 秒归档租约，失败延迟 60 秒。坏记录不阻塞其他复盘。
- 以固定来源身份及真实来源范围幂等归档。重放不重复建单、不覆盖人工编辑、不复活已归档条目；进程重启继续处理队列。

## 4. 确认与回溯

普通 DRAFT 不能自动召回。运维修订问题、原因与有效步骤，填写验证依据并明确改为 VERIFIED 后，同规范化 API / namespace 的对话和 Graph 通过 FTS5 召回最多 3 条，并保存可打开的来源引用及当时 revision。模拟与真实范围隔离，无法证明来源的记录不用于自动召回。词法相关不证明根因相同，当前证据始终优先。

成功回复下的“查看自动复盘”查询 `GET /api/console/memories/reflections/{turnId}`，返回 READY 与记忆、PENDING 或 NOT_CREATED。调查案例展示其调查复盘、最近关联聊天与恢复总结，最多 50 条；每条可打开修订。普通记忆列表支持来源、可信状态和实际范围标识。接口不暴露凭据或上游异常正文。

## 5. 适用性反馈与修订

运维可对成功回复实际引用的版本提交 HELPFUL / NOT_APPLICABLE / OUTDATED 反馈和最多 500 字依据。服务端核对轮次实际引用、当前来源范围、记忆版本与 VERIFIED 状态；每个轮次每条记忆仅一条不可变记录。相同 requestId 与完全相同内容重放返回原记录，改变内容拒绝。

HELPFUL 仅记录有帮助，NOT_APPLICABLE 仅记录本次不适用，不改变全局可信状态。OUTDATED 在记忆库同一事务保存反馈并将对应版本退回 DRAFT、revision 加一，后续 FTS 自动召回排除它；可查看原文和反馈，人工修订、补充新验证依据后重新确认。不因一条反馈自动自授 VERIFIED、扩大执行权限或修改恢复预算。旧数据中未保存 revision 的引用继续可读，但不能用于否定当前经验。

接口：`POST /api/console/memories/{id}/feedback`，入参 requestId、turnId、revision、kind、note；`GET /api/console/memories/feedback/turns/{turnId}` 回显本轮持久化反馈。反馈表位于 SQLite 记忆库；无跨主库外键，轮次真实性由服务端检验。

`BUSINESS_DICTIONARY_OR_CONFIG`：反馈类型是影响可信状态的固定协议代码枚举，不能由运营字典新增；正文与验证依据仍为可维护知识。

## 6. 异常与权限

所有读写需要 OPERATOR，写请求需要同源与控制台写头。请求期间换址、删除连接或移除任务所在监控范围时，迟到结果不能成为成功回复或自动复盘。归档失败不回滚已完成的外部动作；保留主库快照继续尝试。召回不可用时继续使用本次证据，不增加权限。

## 7. 验收标准

1. SQLite 与专用 PostgreSQL 均能从成功对话和调查生成 DRAFT；失败模型、未绑定对话不生成。
2. 同请求重放和队列重放不重复建单，不覆盖人工修改；归档条目不被重新激活。
3. 伪造 VERIFIED 出队快照被拒绝，其他正常条目仍能归档。
4. 人工核验之前没有自动召回，确认之后同来源问题可找到引用；其他 API / namespace 及模拟记录不会混入。
5. 失败和取消的总结明确没有恢复验收，不产生已解决案例。
6. 用户可从回复或案例查看总结、补充验证依据、确认与归档；历史来源身份不变。

7. 有帮助与本次不适用不改变可信状态；已过期反馈只对实际引用版本生效，退回待确认后不再召回，人工重新验证后可召回新版本。
8. 反馈精确重放只保存一次；改写重放、伪造轮次引用、跨来源和陈旧版本拒绝，升级前无版本引用仍可读取。

## 8. 依赖与边界

FTS5 是词法回溯，无向量匹配、自动知识合并或模型自主确证。PostgreSQL 模式的记忆文件和主库无法跨库原子提交，通过主库出队及幂等落库衔接。未自动回填升级前旧任务；本机替身不等同真实生产恢复结果。

## 多空间与可用性

多 namespace 恢复经验按本空间证据生成摘要以支持原调查召回，不将其他空间诊断正文或日志外发到本空间；父经验退出 VERIFIED 后，摘要也不再自动召回。辅助总结读取失败时案例显示学习缺口，不能阻断主事实和批准入口。完整规则见 SQLite 与排障记忆 PRD。
