# 站点开通与自动托管 PRD

日期：2026-11-13。状态：首期 Agent 实现，平台阶段生产端与真实恢复待联合验收。依据：[迭代方案](../../docs/站点开通部署自愈与持续学习_迭代方案.md)。

## 目标与边界

以稳定平台实例、provisioningId、deploymentVersion 保存一次站点开通账本，冻结工作空间与站点，聚合平台阶段、明确资源、调查案例和唯一恢复 Run。项目、namespace 和 CR 尚不存在时也可展示失败及平台错误。沿用共享 OPERATOR 工作空间，不能宣称提供租户自助权限隔离。

本期落地 P1 / P2 的 Agent 侧首版与恢复效果账本。阶段协议为待平台确认的 v1 契约，测试夹具由本仓库定义，并非平台实际导出证明。原平台目录及 `/api/deployment-events` 保持各自用途，不将目录推断为阶段事件或恢复授权。

P0 的在线版本更新、RBAC 补齐、真实恢复演练未执行。P3 新动作及平台 / Operator 执行协议，P4 的经验适用条件、候选知识发布与版本回放评测尚未实现；本期不把效果计数描述为已完成持续优化评测。自动补采采用既有一次有界采证，不引入模型驱动的多轮探测。

## 阶段事实

- 独立 v1 接收端、事件收件箱与增量游标补偿；按平台实例 + eventId 去重，按发布 sequence 接受更新。相同事件换内容、相同序号冲突、较新业务时间倒退均拒绝。旧事件保留回执，不覆盖最新阶段。
- phase 不硬编码为四类 CR 串行；dependencies 按平台声明展示。completedUnits 必须表示业务子步骤完成数量。阶段变化、阶段状态变化、完成数量增加才能更新有效进展时间；序号、轮询和心跳不延长停滞阈值。
- 分开保存平台发布开始、阶段开始、最后有效进展、最后观察时间。发布开始时间不可修改，总时限不随事件或调查重置。`state=SUCCEEDED` 仅表示当前阶段成功；`terminal=true` 才表示平台开通结束，仍不能替代应用验收。
- 一旦 namespace / 集群 API / projectId 建立，不允许在原发布中换址。资源 UID / generation 的新事实可见，但旧调查结果不能采纳，既有 Run 不能执行新目标。
- 分页逐页事务提交游标与事件，后页失败保留已提交事实；达到页数上限下轮继续，410 清空游标后有界重扫；不根据空页、缺页、403 或网络故障删除、终止站点。
- 推送事实不等于当前平台授权。自动调查、转交与恢复前以当前平台凭据读取单任务阶段，并验证身份。凭据轮换不会改变业务幂等身份；原授权摘要不再有效，连接凭据轮换须重新保存策略核验。

## 托管策略

策略包含版本、操作者、工作空间、明确 siteId 或 projectId、冻结连接 API / revision、一个已纳管 namespace、等级、停滞阈值、总时限、调查预算和冷却时间。两种业务 ID 都填时取交集；启用范围重叠拒绝。身份范围不可编辑换址，须暂停旧策略后新建。namespace 须来自原连接 1–20 项明确监控清单，不自动纳入新 namespace。

| 等级 | 行为 |
| --- | --- |
| OBSERVE | 自动观察与显示异常，不自动调用模型 |
| DIAGNOSE | 异常时进入原只读调查队列，保存采证和方案，不转交恢复 |
| APPROVAL | 当前证据命中允许手册后，通过原案例服务核验完整目标并复用唯一 Run；必须批准当前 planId |
| AUTO_LOW_RISK | 同上；还需进程 autoRetry、独立自动恢复开关和验收记录引用，满足全部门禁才自动执行；未开启时等待人工批准 |

默认关闭阶段同步和低风险自动执行，默认没有托管策略。健康开通不诊断。平台前置失败且无 CR 时，用规则保存平台调查及 DRAFT 复盘，明确错误、依赖和缺口，转人工；不构造虚假 CR、kubectl Scope 或恢复任务。

同发布 + 故障证据指纹只触发一次，心跳不触发新调用。策略默认最多 2 次自动诊断，可选 1–3；自动调查与关联 Run 的诊断共享此上限。原模型调用失败、超时、进程中断均不自动重放；有效新证据才可能进入剩余预算。Run 调用另有持久化意图与最多 3 次上限。

全实例自动调查队列默认最多 20 条，可配 1–100；策略冷却 30 秒至 24 小时；同策略 5 分钟内 3 次失败熔断。每轮最多核验 10 个站点，40 秒轮次预算。首版一个集群只有一个自动恢复槽位，因此单项目至多一个；配额满时保留调查结果转人工，不自动重试转交。未知动作结果保留槽位，先对账后由人工核验。

策略更改版本、暂停、站点暂停、范围收回、凭据更改均使原队列 / 未执行恢复失效。采证前、模型前、采纳方案前、恢复意图前和外部写入前检查。已经受理的动作仍按原 actionKey 只读对账和验收，暂停不宣称撤销。不能通过新案例、新 requestKey 或终态 Run 重置发布预算。

## 诊断、恢复和学习

沿用原规则分类、Graph 调用锁、范围记忆、白名单采证与 strictPlatformContract。模型前先持久化采证快照；模型失败仍可查看证据。方案新增候选原因、支持证据、反对证据、缺失证据、建议动作和验收条件。此结构不授予动作权限。

恢复继续只支持 `platform-transient-retry` v1，保持原配置，不增加重启、删 Job、回滚、容量或数据操作。恢复任务同时冻结平台 API 和执行集群，切换平台后不接管旧真实任务；升级前缺少平台身份的真实账本须人工核验。严格平台快照必须和阶段全部资源一致，依然要求独立同集群身份、namespace、验收目录、UID / 代次及平台双版本校验。

终态与恢复效果同事务落库，区分 VERIFIED_RECOVERY、NATURAL_CONVERGENCE、RECOVERY_NOT_VERIFIED、MANUAL_OR_FAILED、CANCELLED，保存动作键、手册、经验引用及策略版本。只有真实受理并完整稳定验收的恢复可生成 VERIFIED 记忆；其余仍为 DRAFT。效果页展示样本量，不计算无依据的长期自愈覆盖率。

## 页面和接口

新增“站点开通”入口，提供站点列表、阶段时间线、依赖、观察降级、调查证据、关联 Run、暂停 / 恢复、策略编辑和暂停、恢复效果样本。批准 / 停止仍使用原 Run 控制。写接口沿用认证、同源头和 revision；暂停不能绕过版本冲突。

接口与配置见[阶段接入契约](../../docs/站点阶段协议与自动托管接入.md)。主库新增 PostgreSQL V15 / SQLite V10，新增账本和出队与现有主文件共用；不自动迁移旧数据或启动真实托管。

## 验收边界

两种主库共用 `ProvisioningContract`；SQLite 使用独立临时文件，PostgreSQL 只有显式 TEST_DATABASE_URL 才执行。外部平台、集群及模型替身均属于模拟 / 契约测试。平台生产 fixture、现场只读权限、真实恢复受理和三次验收必须单独验收，不能用本地通过替代。
