## 1. 目标与范围

运维为已保存的 KubeSphere 连接启用部署发现，Agent 自动读取 webapp-operator 的部署资源并保存清单。用户自行决定忽略或交给 Agent 生成排查方案；自动发现本身不调用模型，也不自动创建恢复任务。

显式启用[站点自动托管](站点开通与自动托管_PRD.md)后，受权平台阶段的明确失败或停滞可按范围策略进入同一调查队列。发现扫描自身仍不诊断；自动接管前后重新核验平台授权、冻结连接和资源代次，指纹去重与发布级调用预算持久化，失败模型不自动重放。采证在模型前先落盘，分析失败仍可查看已有证据。自动与人工恢复转交共用原案例服务，不新增绕过校验的入口。

本版按连接独立保存的 1–20 个明确命名空间发现 ProjectPostgres、ProjectRuntime、PlatformRelease、ServicePublish 四类 CR。不扫描全部命名空间、普通工作负载或 DevOps 流水线，不从 CR 猜测平台 provisioningId，不将多个 CR 拼装成平台发布任务。一个资源的一个代次作为一条发现记录。首次启用收录当前清单，包括已 Ready 的资源；无法重建此前已删除的发布历史。

多连接的只读发现与现有单集群恢复工作流分别运行。“交给 Agent”只读排查不调用 kubectl、不重试、不修改集群；恢复通过案例详情中的显式转交入口，须经平台完整目标核验、独立执行身份、批准、预算及验证流程。

## 2. 用户与操作流程

使用现有 OPERATOR 账号、共享工作空间。在「部署任务」页，每条连接展示名称、命名空间、启用状态、最近同步尝试和错误，可启用 / 暂停、立即同步。默认均未启用；启用后后台自动开始同步，不依赖页面保持打开。页面可编辑监控命名空间清单，每行一个；首次沿用连接默认 namespace，随后独立持久化，编辑默认 namespace 不改变已选范围。须事先授予对应只读权限；拒绝空清单、重复、非法名称、通配符及超过 20 项。暂停保留范围，范围编辑使旧扫描租约失效。

发现清单展示资源类型 / 名称、来源连接、命名空间、代次 / 发布版本、集群部署状态、Agent 处理状态和首次发现时间。集群状态与 Agent 状态分开展示，CR Ready 不能视作平台和应用验收成功。observedGeneration 不等于当前 generation 时显示等待当前代次。

用户可按连接、Agent 状态筛选，每页 30 条，提供上一页 / 下一页与总数。默认按首次发现时间倒序，持续同步不会把同一条记录不断提到列表顶部。

操作包括：

1. 「详情 / 方案」查看最后同步状态、错误、选择操作员与时间，以及已有排查方案、采证时间和来源。
2. 「交给 Agent」持久化本次选择并排队；后台重新读取当前资源，执行诊断 Graph，完成后显示已有方案。
3. 已完成或失败的记录可手动「重新排查」，不会自动循环调用模型。
4. 「忽略」保留记录且继续同步集群状态；可恢复待接管，运行中或排队中不能忽略。
5. 「询问 Agent」创建关联此发现任务及原连接的对话上下文，用户发送消息后才调用模型；聊天可参考当前已同步状态和已有方案，成功对话仍可保存排障思路。

## 3. 身份、去重与状态

去重身份为连接 ID、API 地址与命名空间的摘要、CR UID、generation。相同身份只更新摘要及最后同步时间；不同连接、资源重建或新代次分别记录，不能用旧记录授权新对象。修改连接名称或轮换凭据不新建资源代次。

完整同步中缺失的资源标记已不在清单，同 UID 的旧代次标记已有新代次，连接更换目标后的旧记录标记连接目标已变更。旧记录保留历史但不能重新接管。同步异常、权限拒绝、分页不完整或超限时，本轮不更新清单，也不把资源误标为删除。

Agent 状态：

| 状态 | 含义与转移 |
| --- | --- |
| PENDING | 待接管；用户可选择排查或忽略 |
| QUEUED | 已排队；等待后台领取，不重复接管 |
| RUNNING | 排查中；独立租约所有者执行 |
| DONE | 已生成方案；允许用户显式重新排查 |
| FAILED | 读取、身份核验失败或处理超时；手动重试 |
| IGNORED | 已忽略；可恢复待接管，同步不会重置选择 |

同一选择 requestId 重放返回已有处理状态，不能重复入队。每次新操作检查 revision，记录操作员和选择时间。运行租约 120 秒；中断或超时后转失败，禁止自动重放和迟到结果覆盖。方案保留采证时的资源摘要与时间，不覆盖较新的同步状态。

## 4. 诊断与权限边界

排查前后均通过原连接重新 GET 指定资源，核对 UID、命名空间、类型和 generation；连接更换目标、资源被删除或新代次出现时拒绝旧结果。提交结果时再次检查连接目标、清单存在状态及租约。

使用现有 Spring AI Alibaba Graph 的脱敏、分类、记忆召回与诊断能力，传入纯证据，不构造恢复或 kubectl Scope。命令节点跳过，方案 automatic 固定 false。启用模型时使用当前模型，否则使用规则手册；模型失败沿用 Graph 的手册回退，界面显示来源。

采证包含 CR 身份、有限标签、发布版本与 status，以及通过 ownerReference UID 链核验的 Deployment / StatefulSet / Job / ReplicaSet 和 Pod、容器状态、相关事件及有界日志。不采集 Secret、完整 spec 或任意业务数据。采证与关联对话共用只读采集器；每类最多 500 对象、总共最多 24 请求，异常优先最多 4 个 Pod、4 次日志，每次 60 行 / 4096 字节；单页最多 1 MiB，后台软预算 20 秒、对话 5 秒，连接与读取超时各 2 秒，单个进行中的请求仍受自身超时限制。归属链最多展开 8 轮，分页重复、无归属、权限拒绝及预算不足均记录缺口。状态文本脱敏，原连接 Token 的精确匹配也脱敏。采集缺口明确显示，不以没有采到 Pod 作为健康证明。

对话绑定 discoveryId，并禁止与另一连接或恢复任务混用；会话恢复后保留此关联。删除连接后保留发现记录与历史文本，但不能继续读取或排查；更换地址后的旧对话拒绝混用新连接。完成的调查方案及成功关联对话自动生成待确认复盘，不能自动确认为已解决；运维可核实修订后再用于后续召回。请求期间换址或移除实际任务 namespace 后，迟到回复不能写为成功或生成复盘。发现会话冻结任务实际 namespace，连接默认 namespace 的编辑不使其漂移；从监控范围移除该空间则停止继续调查。

## 5. 同步与安全

- 每 30 秒调度已启用连接；每个连接单独持有同步租约，持续 60 秒，成功或失败后至少间隔 30 秒。立即同步可提前触发，但不会并发重复读取同一连接。暂停或编辑连接后，旧请求结果失效。
- 固定读取 `/apis/platform.lanhao.io/v1alpha1/namespaces/{namespace}/{plural}`，列表使用 limit=100 并处理不透明 continue；全部选中 namespace 的四类清单全部成功后才入库。所有选中 namespace 共用最多 100 个请求、2000 条资源和软时限 40 秒，每页上限 2 MiB；连接 / 单请求读取超时各 2 秒，不重试。超限提示缩小范围，本轮不采纳部分清单。
- 需要四类 CR 的 get / list 权限；深度采证还需要上述工作负载、Pod、events 的 list 与 pods/log 的 get 权限，不足时保留已有 CR 证据并报告缺口；Pod 连接测试成功不代表 CR 权限齐备。401 / 403 / 404 等展示安全错误；不回显上游正文、Token 或 CA。TLS 使用连接自己的 CA，始终校验证书链和主机名，不跟随重定向。
- 所有 API 要求 OPERATOR；写操作继续要求 `X-Console-Request: 1` 及同源校验。源启用状态、发现摘要、忽略决策、排队、方案与关联会话存入当前主库，SQLite 与 PostgreSQL 均支持。旧库由增量迁移升级，不搬迁原数据。
- 当前没有自动历史清理、批量接管、取消运行中诊断或跨租户隔离。页面每 5 秒刷新状态，只有待接管记录不会占用诊断队列。

`BUSINESS_DICTIONARY_OR_CONFIG`：四类 CR、Agent 处理状态和存在状态是版本化协议代码枚举；来源连接、命名空间和发现开关是运维配置；资源列表与 phase 来自实时集群，不能硬编码业务字典。轮询、分页、响应上限和租约属于服务端资源保护策略，页面不能修改恢复预算。

## 6. 接口

| 接口 | 语义 |
| --- | --- |
| GET /api/console/discovery/sources | 已保存的来源开关、版本、最近尝试与错误 |
| PUT /api/console/discovery/sources/{connectionId} | 按 revision 保存 enabled 与可选 namespaces；不传范围保留已有值，默认未启用 |
| POST /api/console/discovery/sources/{connectionId}/sync | 立即同步已启用来源；进行中返回当前状态 |
| GET /api/console/discovery/tasks | connectionId / state / offset 筛选分页，items 与 total |
| GET /api/console/discovery/tasks/{id} | 资源摘要、处理状态、方案和人工选择记录 |
| POST /api/console/discovery/tasks/{id}/select | revision + requestId 显式排队，幂等重放 |
| POST /api/console/discovery/tasks/{id}/ignore | revision + ignored 更新忽略决策 |
| POST /api/console/sessions | 可选 discoveryId，必须关联同一连接且不能同时绑定 runId |

## 调查案例与受控转交

发现记录 ID 同时作为调查案例 ID，聚合其方案、目标证据、关联对话及显式转交后的恢复账本和最多 100 条命令审计。每条发现记录固定一个资源代次；多个记录只有经同一平台发布核验后，才能共享同一个完整恢复账本，不根据名称或标签自行拼接发布。

案例详情可从已同步目录选择关联平台任务，也可填写 provisioningId（十进制字符串）；点击“读取平台发布信息”后由受权平台返回生命周期版本和验收目录，不从 CR 发布版本推测。版本只读，任务 ID 修改后清除预览与确认。先调用平台受权快照并重新 GET 所选 CR，核对 UID / generation；必须拿到完整、最多 10 个目标且包含所选 CR，所有目标 namespace 均在独立执行身份的允许清单中。预览成功后用户确认转交，服务端再次核验，随后原子保存案例关联与 Run。页面只读 Token 不被复用为写凭据。

仅严格 Kubernetes 模式、同执行集群、当前清单 PRESENT 且有验收目录时可转交。其他情况显示具体阻断原因。不会因 404、冲突或模型建议降级调用旧 retry。恢复仍由 RunEngine 监控、Graph 诊断和策略判断；可选命令采证仍在 Run 的租约、归属和审计下执行。自动与批准模式遵循服务端配置；低风险 WAITING_APPROVAL 可在案例详情批准当前 planId，也可在尚未下发时停止后续恢复。已执行动作不能撤销。

案例只能关联一个 Run；同一平台发布的其他案例或事件已有 Run 时复用原账本，已终态也不能重开预算。重放返回原关联，不访问平台或重下发；更换任务 / 版本 / 验收目录拒绝。身份校验失败的转交不创建 Run。恢复状态持续可从原发现对话查看，并与只读建议区分。

案例的辅助总结读取失败时返回 learningWarning，仍显示主案例和恢复操作；主库或身份失败不降级。

接口：`GET /api/console/discovery/tasks/{id}/case`；`POST .../{id}/platform-registration` 接收 revision 与 provisioningId 以查询平台发布身份；`POST .../{id}/recovery-preview`；`POST .../{id}/recovery`。后两者接收 revision、provisioningId、deploymentVersion、verificationProfile，要求原认证与写头。平台严格接口仍是外部依赖；Agent 入口本机验证不代表租户后端已完成接入。

## 7. 验收标准

1. 默认不扫描；启用后仅读取明确选中的命名空间与四类列表，处理分页且不访问 Secret / 全集群接口。
2. 多次同步相同 UID / generation 只生成一条待接管记录，未选择时不调用模型、kubectl 或恢复 API。
3. 不同来源及新代次分别记录；缺失、换址和替代资源不能被旧任务接管。错误同步不伪造删除。
4. 选择操作有认证、同源、revision 和 requestId 校验；重复点击不重复调用，忽略持续生效。
5. 排查前后身份核验，Graph 无命令 Scope，方案明确只读，恢复任务数和命令审计数保持不变。
6. 并发后台领取仅一位所有者；超时不自动重放，旧结果不能覆盖手动重试或新代次。
7. 两种数据库重建仓库后仍有来源、摘要与会话关联；删连接保留历史并阻止再次读取。
8. 页面可完成范围编辑、启用、同步、筛选、分页、忽略、接管、查看目标采证与关联对话，失败反馈明确；窄屏无整体横向溢出。
9. 案例中可预览平台完整目标后转交受控恢复；同发布已有终态账本也必须复用，不能重置预算。DEMO / 执行集群不匹配 / 不严格的平台契约 / 未授权 namespace 均拒绝转交。

真实 CR 读取、现有连接命名空间是否包含目标应用、账号 get / list 权限和真实模型诊断仍须分别验收。本机替身与规则诊断成功不能标记真实部署恢复成功。

## 平台站点部署目录

服务端显式配置 `AGENT_PLATFORM_CATALOG_ENABLED=true`、`PLATFORM_BASE_URL` 和 `PLATFORM_TOKEN` 后，每 30 秒读取受权平台目录，保存站点、任务、域名、阶段、项目、集群 API 与 namespace。来源按平台地址与凭据隔离；默认关闭。每次最多扫描 5 页，可配置 1–20 页，每页最多 100 条，共享软预算 40 秒、单次读取 5 秒、响应上限 2 MiB，不重试或跟随重定向。部分扫描及网络失败保留上次数据并显示缺口；401 / 403 清空该来源缓存。发现不调用模型或创建恢复任务。

平台地址默认要求 HTTPS。本机目录联调可显式设置 `AGENT_PLATFORM_CATALOG_ALLOW_LOOPBACK_HTTP=true`，仅接受 `http://127.0.0.1` 或 `http://[::1]`，仍需正常平台鉴权，不接受 localhost、其他主机名、缩写 IP、内嵌凭据、查询参数或重定向。此开关仅作用于目录读取；Kubernetes 恢复模式继续拒绝 HTTP 平台地址。

Windows 本机可运行 `scripts/configure-local-platform.cmd`，优先使用 PowerShell 7，缺失时回退系统 5.1，无需管理员权限或修改系统执行策略。在终端隐藏输入已有平台登录 Token，或使用当前进程的 PLATFORM_TOKEN。脚本先读取第一页验证授权、响应格式和字符串 ID，再使用 Windows 当前用户 DPAPI 加密保存到忽略目录 `secrets/local-platform/token.dpapi`，目录 ACL 仅允许当前用户；重复执行可更新当前用户的凭据，失败不覆盖旧 Token，不回显上游正文。它不创建账号、不延长会话、不启动恢复，也不自动切换运行中的 Agent 配置；平台重启或会话过期后须重新登录配置。

已有本机加密凭据后，可通过 `scripts/start-local-platform-agent.cmd -Restart` 显式加载目录配置；入口仅用于本项目SQLite与本机8100，保持DEMO恢复。启动前重新鉴权，检查活动恢复、未过期对话和排队/运行中调查，配套在线备份数据库与主密钥；只有原PID、创建时间、Java运行包和SQLite profile均匹配才可停止原进程。凭据只注入目标进程环境，不进入启动参数；启动后健康观测超时不自动重复启动仍存活的进程。该入口依赖本机Python与JDK21，已完成备份辅助逻辑验证和双版本语法检查，实际目录切换仍需运行验证。

`BUSINESS_DICTIONARY_OR_CONFIG`：回环 HTTP 开关是默认关闭的部署联调配置；允许的回环 IP 与 HTTPS 恢复要求属于固定安全边界，不采用业务字典。

页面每页 30 条，提供同步、查看阶段、选择同集群连接并“监控并关联资源”。项目未创建时只展示平台阶段；不能把没有 CR 当作健康。关联操作重新查询受权任务身份、核对集群，按 revision 将实际 namespace 加入所选连接的明确监控范围，扫描后仅返回相同项目及 namespace 的当前 CR；用户再选择是否交给 Agent。无 CR 时保留监控范围等待后续扫描，不自动调查。

接口：`GET /api/console/platform-catalog?offset=...`、`POST .../sync`、`GET .../investigations/{id}`、`POST .../{provisioningId}/monitor`（connectionId）。目录记录使用当前主库，支持 PostgreSQL 与 SQLite。

只读关联读取受同一数据范围授权的 `/provisioning-instances/{id}/catalog-entry`，不要求恢复验收目录；缺少验收配置的项目仍可加入明确 namespace 监控。恢复快照和实际恢复继续要求全部门禁。平台目录与详情固定 JSON，跨仓契约使用平台真实映射生成的响应验证消费者。

目标采证在 ownerReferences 证明的归属内，优先选择失败工作负载、其所属 Pod、异常容器，再选择未就绪、健康及已完成 Pod；已成功完成的 Job Pod 不因 Ready=false 被视为异常。最多保留 8 个工作负载摘要、4 个 Pod 和4条日志；超过采样上限时显示 WORKLOAD_SAMPLE_LIMIT / POD_SAMPLE_LIMIT。工作负载状态和容器证据都不自动升级为决定执行的证据；名称提示不能授予归属或执行范围。
