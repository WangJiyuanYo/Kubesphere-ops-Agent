## 产品目标与范围

为单机运维提供不依赖 PostgreSQL 的完整 SQLite 模式。把已经解决的问题及排查思路持久化，在后续对话和诊断中检索参考，减少重复排查。范围来自用户明确选择的“完整 SQLite 模式”，以及 KubeSphere 连接信息入 SQLite 的补充要求。

本轮提供 FTS5 词法检索、中文双字组和技术词处理；不提供向量检索、自动数据库迁移、任意历史任务回填或模型自主修改恢复策略。

## 用户角色与场景

沿用 OPERATOR 运维账号和共享工作空间。运维可手工记录案例、从已完成对话保存思路、核实并标记已验证，也可归档失效经验。自动恢复任务成功后生成案例，供下次排查参考。

记忆保留创建时的服务端模式作为来源元数据；自动召回按实际调查来源隔离：模拟恢复为 DEMO，真实连接为规范化 API 与命名空间的摘要，恢复任务为冻结的执行集群与目标命名空间集合。DEMO 进程内的真实只读对话也使用真实来源范围，不自动参考模拟案例。此范围用于诊断可信度，当前仍是共享运维工作空间，不构成多租户权限体系。

## 当前功能规则

### 完整 SQLite 存储

- 通过 `sqlite` profile 启用，默认文件 `./data/agent.db`，服务端可指定其他路径。任务、事件、恢复身份与预算、审计、通知、模型配置、KubeSphere 连接、聊天、记忆和记忆出队记录全部持久化。
- KubeSphere 名称、API 网关、控制台链接、命名空间、加密 Token 和可选加密 CA 保存在主 SQLite 文件；重启后仍可读取。LLM API Key 同样加密，接口只返回配置状态。CA 规则见管理控制台 PRD，旧记录无 CA 字段继续兼容。
- 按连接保存部署发现开关、CR 摘要、忽略决策、手动诊断队列及方案，对话可关联发现记录；删除连接保留发现历史。仅生成排查方案不自动成为已解决记忆，仍可从成功对话人工保存思路。规则见部署发现与手动接管 PRD。
- 默认 PostgreSQL 模式继续支持，记忆位于独立 `./data/agent-memory.db`。切换 profile 选择另一套数据，不自动复制旧库。
- 两种主库保留请求幂等、活动任务唯一、发布周期唯一、过期租约禁止写入、通知身份与预算等原契约。SQLite 使用外键、WAL、IMMEDIATE 事务及有界等待；仅支持本地持久盘上的单机单实例运行方案。

### 记忆字段与可信状态

- 标题最多 120 字符；问题、原因、解决步骤、验证依据各最多 4000 字符；标签最多 300 字符。标题、问题、解决步骤必填，已验证时验证依据必填。内容按现有脱敏规则处理，页面按纯文本渲染。
- `DRAFT` 待确认：可手动搜索和编辑，不参与自动召回。新建和从对话记录默认选择此状态。
- `VERIFIED` 已验证：运维明确填写依据并确认，或来自受控恢复成功的任务，参与自动召回。运维确认是人工判断，不等于 Agent 自动重跑验证。
- `ARCHIVED` 已归档：有效搜索和自动召回排除，选择归档过滤后可查看并编辑恢复。不硬删历史来源。
- 编辑须携带最新 revision，冲突返回 409；不可静默覆盖其他人的修改。保存失败保留表单供修正。

### 来源与自动归档

- MANUAL 来自手工录入，以请求身份防重复；CHAT 绑定真实 SUCCEEDED 聊天轮次，同轮次重复记录返回原记忆。
- CHAT 记忆从会话核验来源后冻结范围；连接换址或命名空间变化后拒绝将旧轮次记录到新环境。无目标的思路保存为未绑定，不参与自动召回。旧 DEMO 记忆迁移为模拟范围，无法证明来源的旧真实记忆保留但不自动用于真实调查。
- RUN 绑定任务 ID；自动 VERIFIED 必须同时有固定动作键、可信非空恢复受理 ID、恢复状态 SUCCEEDED、实际尝试、稳定验收与诊断方案。attempts 仅代表持久化意图预算，不能单独证明执行。未执行恢复的成功任务、失败或人工处理任务不自动确认为解决案例。
- 记录冻结的原故障证据、受理动作、手册、检查与修复建议、连续验证次数与依据；恢复后的 Ready 不能覆盖用于回溯的原故障码。根因明确标记为经过恢复验收的假设，不等于独立证明因果。自动拼接超过字段容量时截断；手工超长输入拒绝。
- 受控恢复成功与成功案例出队记录同事务提交；其他自动复盘与源结果同事务提交，每 5 秒处理最多 10 条；失败延迟 60 秒，不阻塞其他案例。跨主库与记忆文件无法同事务时，确定性来源身份保证重放不重复。重放不得覆盖人工修改或复活已归档案例。
- REFLECTION 自动复盘关联调查、成功对话及未恢复成功的终态任务，默认 DRAFT；与源结果同事务保存队列快照，后台幂等归档。成功对话正文只是建议，失败 / 取消 / 转人工任务只记录实际轨迹与缺失证据，不能伪造已执行或已验证。失败模型回复和未绑定对话不自动总结。自动工作器拒绝任何试图授予 VERIFIED 的复盘快照。
- 页面成功回复下可查看自动复盘，显示 READY / PENDING / NOT_CREATED；来源为“Agent 自动复盘”。运维补充验证依据并确认为 VERIFIED 后才参与同来源 FTS5 召回。详细规则见 [自动复盘与学习_PRD.md](自动复盘与学习_PRD.md)。
- 不自动回填升级之前已完成任务，不承诺提取初始全部故障日志；记录以任务保存的诊断和验证结果为准。

### 检索、对话与 Graph

- 页面支持搜索与状态过滤，默认排除已归档，最多返回 50 条；空查询按更新时间展示。无结果显示空态。
- FTS5 使用中文双字组、英文技术词及驼峰拆词。查询词被转义并参数化，用户不能直接运行 SQL 或 FTS 运算符。匹配已验证优先，再按相关度排序；词法匹配可能出现不相关经验，须结合当前证据核验。
- Graph 顺序为 `sanitize → classify → recallMemory → generateCommands → assessCommands → executeCommands → analyzeResults → diagnose`。动作分类仅依据当前证据；按本次显式来源范围自动召回最多 3 条已验证经验，供命令规划和最终诊断参考。每次 Graph 调用显式覆盖记忆范围，未绑定环境时不自动召回。可选只读命令由独立 Java 规则审核，结果只能否决原权限，完整规则见 [kubectl受控排查_PRD.md](kubectl受控排查_PRD.md)。
- 对话依据本轮问题及只读上下文召回，支持有模型和规则助手两种方式。结果附真实记忆 ID、标题和来源，保存到历史轮次或任务诊断；页面引用可打开记忆详情。引用代表被提供的参考资料，不保证模型实际采用全部建议。
- 历史内容标明“仅供参考”，不是本次根因证明或操作授权；记忆不提供执行工具，不改变手册、预算、批准及验证。模型本身不拥有写入或确认记忆的工具。

## 经验反馈

SQLite 记忆库保存每次经验适用性反馈（requestId、memoryId、引用 revision、turnId、来源范围、类型、依据与时间），与记忆降级同事务提交。HELPFUL / NOT_APPLICABLE 保持可信状态；OUTDATED 使实际引用的当前 VERIFIED 版本回到 DRAFT，停止召回，人工修订验证后可重新确认。唯一约束为 requestId 与 (memoryId,turnId)，重放不重复变更；历史反馈不覆盖新版本。交互与接口规则见《自动复盘与学习 PRD》。

## 权限、数据与接口语义

`/api/console/memories` 提供 GET 搜索、POST 新建，`/{id}` 提供 GET 详情和 PUT 修订。全部需要 OPERATOR；写请求沿用同源与 `X-Console-Request: 1` 规则。新建不得直接归档；来源由服务端根据手工请求、真实聊天轮次或任务决定，编辑不改变来源。

`BUSINESS_DICTIONARY_OR_CONFIG`：可信状态和来源类型属于稳定生命周期代码枚举；数据库文件路径和运行模式属于服务端配置；记忆正文和标签是运维维护的知识，不充当可执行策略、业务字典或恢复开关。

## 异常与恢复路径

记忆召回故障时降级为仅依据本次证据，禁止用历史建议补足缺失执行授权。归档失败保留出队记录退避重试，不回滚已成功的任务。SQLite 写锁等待有界，冲突按原接口错误规则处理，不绕过租约或唯一约束。

进程重启继续读取持久文件与未处理出队记录，凭据解密要求原主密钥。首次创建记忆结构由独立迁移历史管理，不能手工删除历史表强制重建。

## 非功能需求与部署边界

数据库、记忆文件及主密钥须配套备份。SQLite 在线备份使用 backup API，或停服务后复制；不能忽略未合并 WAL。容器数据目录须挂载持久卷，当前 Kubernetes 示例单实例 Recreate，避免滚动期间两个实例争用同一记忆文件。默认检索不自动清理历史，不承诺多实例共享记忆、容量指标或语义推理匹配。

## 验收标准

1. 无 PostgreSQL 可启动 SQLite profile，主库外键、WAL 生效；KubeSphere 与 LLM 凭据密文存储，重建仓库和重启服务后可用。
2. 并发认领只获一个任务，过期 owner 不能回写；同发布版本不能重置预算。通知失败重试保持签名事件身份，成功停止投递。
3. 中文及 ImagePullBackOff 可检索；编辑同步索引，归档退出有效结果，注入样式查询不改变 SQL 或执行 FTS 表达式。
4. DRAFT 不自动召回；VERIFIED 在对话和 Graph 留存真实引用；模拟案例不进入真实连接调查，不同 API / namespace 的案例不自动混用；无目标会话不自动召回。
5. 历史经验建议重试时，本次认证错误仍必须转人工。
6. 恢复成功生成一次 RUN 记忆，重复处理不重复建单；坏出队记录延迟重试，其他案例仍可落盘；长诊断按上限归档。
7. API 匿名和缺少写头请求拒绝，无验证依据不能确认，过期 revision 返回冲突，同聊天来源重放幂等。
8. 自动复盘以待确认落库，成功对话可查看其总结；确认后下次同来源问题可召回，重复出队不覆盖人工修改或复活归档记录。
9. 页面可记录、搜索、核实、归档和从回复保存思路；窄屏可操作，重启后配置、历史与 FTS 结果保留。

## 依赖与现场边界

JDK 21、SQLite JDBC 与 FTS5；PostgreSQL 模式另需主库。真实集群、模型协议、现场日志脱敏及备份恢复仍需环境验收。本机 HTTP 替身和模拟部署只证明本机链路。

## 自动归档的补充约束

自然收敛或缺少动作凭据的成功任务只生成 DRAFT。迁移将未经人工编辑、旧版本自动生成的 RUN / VERIFIED 记录重新置为 DRAFT，要求核验；不改变人工编辑后的可信状态。

多 namespace 发布保留组合范围的完整经验，并为各 namespace 生成 RUN_COMPONENT 摘要，只包含本空间 CR 证据与整体动作引用，不复制其他空间的诊断或日志；自动召回还要求父 RUN 处于 VERIFIED，父记录归档即停止摘要召回。其他集群和未授权空间继续隔离。

平台目录及来源同步记录与任务共用当前主库。PostgreSQL 模式下辅助 SQLite 记忆不可读取时，案例返回明确学习缺口，主任务及恢复操作仍可展示；主库本身不可读取不承诺继续操作。
