## 两轮优化与复审

### 第一轮：接入状态和生产者消费者契约

复审补出了 C1 的只读授权入口与 C3 的传输格式断点。平台真实映射可通过 -Dagent.contract.catalog-fixture=<绝对路径> 导出；Agent 的 src/test/resources/contracts/tenant-catalog-entry.json 来自该导出，消费者不再只使用自行臆造的理想字段。

独立验证：round1-contract-tests.log，22 项通过；platform-rounds-tests.log，平台 28 项专项通过，包含新路由、匿名拒绝和严格恢复配置仍拒绝。平台真实运行服务尚未部署，fixture 验证不等同两个已部署服务的在线联调。

### 第二轮：经验有效性反馈及证据质量

自动复盘仍以固定模板 DRAFT 落库；保存引用的 revision。成功回复实际引用的经验可反馈 HELPFUL / NOT_APPLICABLE / OUTDATED，支持最多500字依据并保存来源、轮次、版本与时间。OUTDATED 在 SQLite 记忆库同事务退回 DRAFT、版本加一、停止后续召回；人工修订验证后可重新确认。有帮助和本次不适用不自动改变可信状态。每轮每条记忆一条不可变反馈，精确重放幂等，伪造引用、跨范围、陈旧版本和改写重放拒绝。旧无版本引用继续可读，但不能修改当前经验。

复审核对了升级兼容、来源冻结、乐观版本、重放、状态降级、FTS5 召回与重验证，没有让模型获得自授 VERIFIED 或扩大权限的能力。真实排查又验证了 C4，补充异常优先的有界采证回归与实际失败组件复验。

独立验证：round2-feedback-tests.log，82 项通过，覆盖 SQLite 和真实专用 PostgreSQL；live-evidence-fix-tests.log，4 项采证专项通过。页面实际操作见 review-memory-feedback.png：创建演示 Run → 诊断 → 批准 → 一次恢复 → 三次验收 → 自动归档 → 原故障召回 → 过期反馈 → 下一轮零引用。事实断言保存在 ui-full-journey.json。该页面演练使用独立 rounds-ui-agent.db、DEMO 适配器与规则模型，未触碰真实集群写入，隔离进程已停止。
