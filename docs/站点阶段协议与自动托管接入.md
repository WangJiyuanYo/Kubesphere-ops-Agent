# 站点阶段协议与自动托管接入

2026-11-13，Agent 侧 v1 提议契约。平台生产端尚未实现 / 验收，不把旧目录或本地替身视为平台已经支持。

## 平台输出

平台状态更新与事件出队须同事务，采用有界退避投递。Agent 接收 `POST /api/provisioning-stage-events/v1`，返回 202 和 `{eventId,watchId,status}`。使用独立 Agent API 账号认证；同 ID 同事实幂等，相同 ID 换内容或同序号冲突返回 409。ID、版本和 workspace 均为字符串，不能经过 JavaScript 数字转换。

事件示例见 [provisioning-stage-event.json](../examples/provisioning-stage-event.json)。必填：schemaVersion=1、eventId、稳定 platformInstanceId、workspaceId、siteId、provisioningId、deploymentVersion、sequence、phase、state、provisioningStartedAt、phaseStartedAt、occurredAt、completedUnits、resources。dependencies 可空，摘要最多 2000 字。阶段码只接受大写字母 / 数字 / 下划线，必须由平台业务语义映射。

`state` 为当前阶段 RUNNING / BLOCKED / FAILED / SUCCEEDED / CANCELLED；`terminal` 表示开通整体已经结束，RUNNING / BLOCKED 不能标终态。发布开始时间冻结；phaseStartedAt ≤ occurredAt，发布时间 ≤ 阶段开始，未来事件最多容忍 30 秒时钟误差。只有业务进度变化才推进有效进展，心跳只增加 sequence 不应增加 completedUnits。

CR 前 resources=[]，projectId / clusterApiUrl / namespace 可空；映射形成后必须完整，不能在同发布中换址。resources 为最多 10 个明确 `{kind,namespace,name,uid,generation}`，仅允许四类既有 CR；全都属于冻结 namespace。该集合用于核验恢复完整目标，不能用单一 CR 冒充整次发布。

平台还须提供以下只读 GET，使用现有受权平台地址和 Bearer Token，保留 URL 上已有网关前缀：

| 接口 | data 内容 |
| --- | --- |
| `/provisioning-stage-events?cursor={opaque}` | `{items:[StageEvent],nextCursor:"...",hasMore:false}`，每页最多 100 条 |
| `/provisioning-instances/{provisioningId}/stage?deploymentVersion={version}` | 该版本最新 StageEvent，必须返回完整身份 |

统一 JSON envelope：`{"code":200,"data":...}`，响应上限 2 MiB。增量游标必须稳定排序、可恢复，hasMore=true 时 nextCursor 必须推进；末页也应返回下一次增量读取使用的水位。游标过期返回 HTTP 410。401 / 403 表示授权失败；5xx、网络失败和半页数据均不能解释为业务失败或任务删除。Agent 不跟随重定向。

推送事件会立即可见，但不能自授当前平台数据权限；自动化前始终读取单任务阶段重新核验，因此两个 GET 同样是自动化的必要依赖。Token 轮换不得改变 platformInstanceId。

## Agent 配置与操作

默认关闭。平台契约联合确认后配置：

```yaml
agent:
  platform-base-url: https://platform.example/agent-api
  platform-token: ${PLATFORM_TOKEN}
  provisioning:
    enabled: true
    platform-instance-id: tenant-platform-test
    max-pages: 5
    queue-limit: 20
    auto-low-risk-enabled: false
    recovery-acceptance-ref: ''
```

也可用 `AGENT_PROVISIONING_ENABLED`、`AGENT_PLATFORM_INSTANCE_ID`、`AGENT_PROVISIONING_MAX_PAGES`、`AGENT_AUTONOMY_QUEUE_LIMIT`、`AGENT_AUTONOMY_AUTO_LOW_RISK_ENABLED`、`AGENT_RECOVERY_ACCEPTANCE_REF`，轮询间隔 `AGENT_PROVISIONING_POLL_INTERVAL` 默认 30000ms。只读本机契约联调可显式启用现有 `AGENT_PLATFORM_CATALOG_ALLOW_LOOPBACK_HTTP`，只接受明确回环 IP；真实恢复仍要求 HTTPS。

保存连接并显式启用其 1–20 个 namespace 发现范围，在“站点开通”新建策略。先 OBSERVE，再 DIAGNOSE，再 APPROVAL。APPROVAL 即使 AGENT_AUTO_RETRY=true 也必须批准当前 planId。AUTO_LOW_RISK 除策略外仍需独立开关、验收记录引用和 AGENT_AUTO_RETRY=true；引用是操作者提供的可追溯验收记录，Agent 不会据字符串自动证明现场已经验收。

| 控制台接口 | 用途 |
| --- | --- |
| GET `/api/console/provisioning-watches?offset=0` | 每页 30 个开通周期、策略及异常 |
| POST `/api/console/provisioning-watches/sync` | 同步增量阶段，不直接执行恢复 |
| GET `/api/console/provisioning-watches/{id}` | 时间线、触发记录、关联 Run |
| POST `/api/console/provisioning-watches/{id}/pause` | `{revision,paused}` 暂停 / 恢复 |
| GET `/api/console/autonomy-policies` | 当前平台策略 |
| PUT `/api/console/autonomy-policies/{UUID}` | 新建 revision=0 / 更新当前 revision；留存操作者与版本审计 |
| GET `/api/console/learning-outcomes` | 终态样本量、手册 / 策略版本和经验引用 |

策略内容：`revision, workspaceId, siteId, projectId, connectionId, namespace, level, enabled, stallSeconds, totalSeconds, maxDiagnoses, cooldownSeconds`。至少指定 siteId 或 projectId；默认推荐 600 / 3600 / 2 / 60。策略 namespace 必须已明确纳管；范围只可新建，不可改址。控制台写入需 `X-Console-Request: 1` 与同源 Origin。批准、取消沿用 `/api/runs/{id}/approve` 和 `/cancel`。
