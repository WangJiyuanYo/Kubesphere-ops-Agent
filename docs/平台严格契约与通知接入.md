# 平台严格契约与通知接入

Agent 消费下述严格契约；关联 lh-tenant 已有实现与专项回归，仍须协调发布和现场验收，不能仅凭源码视为接入完成。Agent 不会把未实现的接口当作已受理，也不会在冲突或 404 后降级调用旧恢复接口。所有接口必须在平台执行服务账号和目标数据范围授权。

## 1. 受权发布快照

```http
GET {PLATFORM_BASE_URL}/provisioning-instances/{id}
Authorization: Bearer <专用服务凭据>
```

```json
{
  "code": 200,
  "data": {
    "id": "9007199254740993",
    "status": "FAILED",
    "version": "release-20261111-001",
    "applicationVersion": "site-release-001",
    "clusterApiUrl": "https://cluster.example:6443",
    "verificationProfile": "tenant-app",
    "snapshotToken": "opaque-non-secret-snapshot-v1",
    "targetsComplete": true,
    "targets": [
      {"kind":"PlatformRelease","namespace":"agent-demo","name":"app","uid":"cr-uid","generation":1}
    ],
    "recovery": {
      "id": "recovery-1",
      "requestKey": "agent_fixed_1",
      "state": "SUCCEEDED",
      "acceptedVersion": "release-20261111-001"
    }
  }
}
```

`clusterApiUrl` 必填且须与 Agent 独立执行集群规范化后相等，并纳入 snapshotToken；别名不能自动视为相同集群。`applicationVersion` 是平台绑定的真实应用版本，应用健康响应必须匹配它；与生命周期 `version` 分别冻结。

`version` 是不可复用的发布身份，同一平台任务的同一版本共用一个 Agent 预算，人工结束后不能通过新事件或新请求键重置预算。资源未创建时 `targets=[]`；资源分阶段创建期间 `targetsComplete=false`，直到本发布的完整目标集合可以冻结才改为 true，避免 Agent 把部分 CR 误认为整条发布。该字段必须是布尔值。平台应在任意目标 UID、generation 或源配置变化时更新 `snapshotToken`。令牌用于并发控制，不得包含访问凭据，长度为 1–512 字符。`targets` 只能包含调用方有权处理的资源，最多 10 个。`verificationProfile` 必须由平台绑定至当前发布，且在 Agent 服务端目录中存在。

`recovery` 可缺省；存在时状态为 ACCEPTED、DISPATCHED、OBSERVED、SUCCEEDED、FAILED 或 SUPERSEDED。动作对账必须保留原 requestKey、id 和 acceptedVersion；平台不得用另一个动作替代同键查询结果。

## 2. 原子恢复受理

```http
POST {PLATFORM_BASE_URL}/provisioning-instances/{id}/agent-recoveries
```

```json
{
  "requestKey": "agent_fixed_1",
  "expectedVersion": "release-20261111-001",
  "expectedSnapshotToken": "opaque-non-secret-snapshot-v1",
  "verificationProfile": "tenant-app",
  "runbookId": "platform-transient-retry",
  "runbookVersion": 1,
  "expectedTargets": [
    {"kind":"PlatformRelease","namespace":"agent-demo","name":"app","uid":"cr-uid","generation":1,"specHash":"sha256-of-canonical-spec","retrySequence":0}
  ]
}
```

平台必须在同一事务或发布锁内完成以下步骤：

1. 核对服务账号与发布归属，并先查询持久化 requestKey。已受理的同键同请求返回原结果，不能再次扣预算或重新触发 Operator；同键不同前提返回冲突。
2. 新请求核验发布 version、snapshotToken、验收目录，以及所有目标 UID、generation、配置摘要和重试序号。任何不符返回 HTTP 409 或 412；原子性必须覆盖正常发布与其他恢复入口。
3. 核验平台组件预算和 runbook 版本，持久化恢复身份及请求快照，提交后由平台既有流程驱动 Operator。
4. 返回 `{"code":200,"data":{"id":"recovery-1","requestKey":"agent_fixed_1","state":"ACCEPTED","acceptedVersion":"release-20261111-001"}}`。

摘要按 UTF-8、SHA-256 和递归键排序的规范 JSON 计算。PlatformRelease / ServicePublish 摘要排除 `retrySequence`，其他类型不排除；平台和 Agent 必须使用相同数值与字符串序列化约定。`snapshotToken` 同时承担平台配置版本校验，不能只信任调用方提供的摘要。

响应丢失后 Agent 先按详情中的恢复身份对账，再以原键重放。平台必须先判定幂等，再执行版本前提检查，避免自身恢复产生代次变化后把合法重放拒绝掉。Agent 不承诺跨系统 exactly-once。

兼容旧平台时，可显式设置 `AGENT_STRICT_PLATFORM_CONTRACT=false`、`AGENT_AUTO_RETRY=false`，并配置 `VERIFICATION_URL`；只允许人工批准的受控试点，不能使用部署事件发现，也不具备平台原子前提保证。

## 3. 部署事件

平台在发布身份创建后调用：

```http
POST /api/deployment-events
Authorization: Basic <独立 Agent 凭据>
Content-Type: application/json

{"eventId":"event-001","provisioningId":"9007199254740993","deploymentVersion":"release-20261111-001","verificationProfile":"tenant-app"}
```

返回 202 和 `{eventId,runId,status}`，刚入队时 runId 可能为空，status 为 PENDING，绑定任务后为 ATTACHED。使用返回的规范 eventId 查询 `GET /api/deployment-events/{eventId}`。同一发布的不同事件号返回最先落盘的规范 eventId，不另开任务。相同事件号改变版本或验收目录返回 409。与既有发布任务目录冲突的事件隔离为 VERIFICATION_PROFILE_CONFLICT，不阻塞其他事件。

事件先落 PostgreSQL，后台再建立 DISCOVERING 任务；若旧任务正在执行，新事件持久化等待。Agent 从平台受权快照发现 CR，绑定后进入 MONITORING。前置阶段失败或资源长期未创建会产生人工处理结果。平台事件发布方需对请求超时与非 2xx 响应重投；本项目未修改现有平台以自动发送事件。

## 4. 应用验收目录

通过 `--spring.config.additional-location=file:./examples/application-production.yml` 载入示例后，按实际环境修改服务端目录。客户端只能指定目录名，不能传任意 URL。健康端点须返回：

```json
{"status":"UP","version":"release-20261111-001"}
```

version 必须代表当前实际提供服务的发布。入口路由、关键依赖的只读连通性等应由该端点汇总，DOWN 或版本不匹配均不能通过；Agent 不执行有副作用的业务探针。探测不携带平台 Token，不跟随重定向。

## 5. 通知与人工接管

配置 `AGENT_NOTIFICATION_ENABLED=true`、HTTPS 的 `AGENT_NOTIFICATION_URL`、至少 32 字符的 `AGENT_NOTIFICATION_SECRET`。该地址是服务端配置，不能通过事件或模型修改。通知默认关闭，事件仍会持久化；开启后可补投积压事件。

WAITING_APPROVAL 和终态转换与通知出队事件在同一 PostgreSQL 事务提交。通知正文仅含 id、runId、state、attempts、planId、deploymentVersion，不含日志或凭据。接收方按 runId 查询完整报告。

- `X-Agent-Event-Id`：固定通知身份，接收方须持久化去重。
- `X-Agent-Timestamp`：发送时 Unix 秒数。
- `X-Agent-Signature`：`hex(HMAC-SHA256(secret, timestamp + "." + 原始正文UTF8))`。

接收方先限制请求体大小，核验时间窗口（建议 5 分钟）和签名，再以固定身份去重、落盘并返回 2xx。使用常量时间比较签名。重投的时间戳和签名会更新，事件身份保持不变。接收成功但 ACK 丢失可导致重复投递，所以语义为至少一次。

默认最多 8 次投递，认领时即扣次数，防止发送后崩溃无限续投。失败按指数退避进入待投；耗尽为 DEAD。`GET /api/runs/{id}/notifications` 可查看状态；运维明确调用 `POST /api/notifications/{id}/redeliver` 才会重置 DEAD 的投递预算，仍使用原事件身份。所有管理接口均要求认证。

## 6. 运行与保留

`GET /api/runs?limit=20&offset=0` 查询任务；`GET /api/runs/{id}/audit?limit=100` 查询独立、追加式审计事件；`GET /api/runbooks` 查询可执行手册；`/actuator/metrics` 在认证后提供工作槽位、步骤耗时和执行失败指标。

每实例默认 4 个槽位，租约续期独立于任务线程，超时定时器独立于续租线程。单步预算 75 秒，采证预算 45 秒，在每个请求边界检查，单个正在进行的请求仍受其连接 / 读取超时限制。超时会中断线程，槽位直到线程真实结束才释放；不响应中断的外部库不会获得新槽位，需运维处理进程。

当前不自动删除审计、报告或发布周期去重账本。制定组织保留策略时须保留发布周期墓碑和动作幂等记录，不能直接删除所有终态后让历史事件重置恢复预算。数据库管理员可修改表；“追加式审计”不等同于抗 DBA 篡改存储。

## 平台目录及只读关联

`GET {PLATFORM_BASE_URL}/provisioning-instances?page=1` 返回 `code=200` 与 `data.items / hasMore`。条目包含十进制字符串 id、siteId、生命周期 version、status、currentStep、workspaceName、projectName、domain、projectId、namespace、clusterCode、clusterApiUrl、unavailableReason；只返回当前平台身份有权查看的任务，不返回配置正文或凭据。项目未创建时保留任务阶段与空项目字段，不能编造 CR。

Agent 通过 `AGENT_PLATFORM_CATALOG_ENABLED=true` 显式启用，平台侧通过 `application.deployment-agent.enabled=true` 启用，默认均关闭。lh-tenant 基址为 `https://platform.example/api/admin/integrations/kubesphere/agent`；平台代理地址还须包含实际代理前缀。平台服务账号需要对应后台菜单及数据范围授权。

用户选择本机8081联调时，仅目录可显式启用 `AGENT_PLATFORM_CATALOG_ALLOW_LOOPBACK_HTTP=true` 并使用 `http://127.0.0.1:8081/api/admin/integrations/kubesphere/agent`，不接受localhost或其他主机名，不跟随重定向，仍需正常平台鉴权。真实恢复继续要求HTTPS。Windows的已有登录Token配置和加密保存见[本机平台目录联调](本机平台目录联调.md)。

目录关联使用 `GET {PLATFORM_BASE_URL}/provisioning-instances/{id}/catalog-entry`。此入口先核对与列表相同的数据范围授权，再返回同格式的单个目录条目；不要求恢复验收配置、不读取集群或执行恢复。严格快照 `/provisioning-instances/{id}` 仍要求项目验收档案及完整目标。目录与恢复接口固定返回 `application/json`，Agent 明确发送 `Accept: application/json`。

恢复仍需平台项目到验收目录的绑定、Agent 侧同名固定健康地址、明确执行 namespace 和独立集群身份。平台升级须与 Agent 的目录详情新路径配套，不自动回退到严格快照或旧恢复接口。
